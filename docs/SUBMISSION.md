# Submission draft — SovereignClaw

**Category:** Personal AI Track

**One-line pitch:** A private daily-work assistant that remembers what matters, turns your priorities into a practical plan, and runs reusable tools only with your permission.

## What we built

SovereignClaw brings a personal assistant's memory, planning, and tools onto a server controlled by its owner. It stores personal facts, conversations, tasks, and reusable Python skills on private persistent storage. The owner decides whether matching memories and tasks may be shared with an NVIDIA model running through Nebius Token Factory.

The daily workflow is concrete: save preferences, add deadlines, build a focused work plan, ask the NVIDIA model to reason over approved context, run a selected skill, and review a daily briefing generated by a background worker. History and preferences survive application restarts. The owner can export the data and delete personal memory.

## Why we built it

Useful assistants need continuity and the ability to act, but users should understand which data leaves their system and which actions actually occurred. SovereignClaw makes those choices visible. Cloud sharing, Python tools, and background work begin disabled. Tool output is real, failed executions stay failed, and offline demo responses are clearly labeled.

## How it works

- Next.js provides the command cockpit, daily task planner, memory explorer, skill registry, privacy controls, and job history.
- The server calls an owner-configured NVIDIA model through Nebius Token Factory's chat-completions API. The exact model ID must come from the owner's available catalog. It records the model used in each completed interaction.
- Local retrieval selects relevant facts; open tasks and tool results enter model context only after owner opt-in. Heuristic redaction and instruction checks run before inference.
- An isolated Linux Python runtime verifies and runs reusable skills with no network, limited filesystem visibility, resource limits, and bounded output. A failed or unavailable runtime refuses execution.
- A supervised background worker creates a daily task briefing and saves its results. Task plans are local proposals, not claims of changes to an external calendar.
- A single-owner access gate protects the production app. Data remains on the host's private persistent volume.

## Claims to keep accurate

The implementation uses custom local privacy checks, Linux bubblewrap, a Python skill registry, and a local worker. It does not integrate NVIDIA NemoClaw/OpenShell, Hermes Agent, or Nebius Serverless. Those are suggested tools in the provided track description, while use of an NVIDIA open source model on Nebius is required. Do not claim that a class name or a demo response proves a cloud integration.

No external email/calendar account is connected. No hardware attestation, GPU latency benchmark, full secret-detection guarantee, or multi-user isolation is claimed. The data files have restrictive permissions; encryption at rest is a hosting configuration responsibility.
